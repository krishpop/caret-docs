Current contract map ​

Caret has several schema layers. Use the contract at the boundary you are changing; a TypeScript union, a model-facing schema and a stored JSON record serve different purposes.

Where each contract is defined ​

BoundarySource of truthRuntime behavior
Supervisor → Mac taskRUN_MAC_TASK_V2 and toTaskSpec in src/supervisor.tsAdvertises parameters, injects trace ID, coerces selected fields; not a strict deep validator
Internal task and resultTaskSpec, TaskProgress, TaskResult in src/cu/types.tsTypeScript contract; not itself a JSON validator

Narrower runtime schemas ​

The internal Predicate TypeScript type is recursive. The model/executor schema supports a leaf, or one all, any, or not wrapping leaves. Nested combinations such as all → any → exists are rejected by that schema. Use a flat all of leaves for an executor-compatible check.

TaskSpec includes all budget dimensions, object plan items and a broader effort union. The supervisor-facing schema exposes step/time budgets, string plan items and medium, high, xhigh effort values. toTaskSpec accepts some values beyond the advertised schema but is not a substitute for strict boundary validation. The generated reference preserves both the internal type and action-schema code so these differences are reviewable.

Via includes native internally for observed execution tiers, while model-facing press and set_value accept auto, ax, or gui.

Schema-lite support versus emitted data ​

All three JSON schemas validate structure; the runtime currently writes agent steps and eligible task summaries. Correction records, shadow/teach values, commit events and predicate DAG fields have more representational capacity than the current writer populates. See recording before interpreting absent values as negative evidence.

Top-level record objects reject extra properties, but some nested extensible objects intentionally allow them (including action args and predicate definitions). Inspect the complete schema before claiming the entire record is recursively closed.
