Maintaining this site ​

Use docs/site/ for the current implementation guide. Keep the older design and operational documents at their existing paths, and link to them with an explanation of their status. Avoid copying an old plan into an API reference.

Commands ​

sh
npm ci
npm run docs:generate        # refresh generated Markdown declarations and schemas
npm run docs:dev             # local authoring server, defaults to loopback :7794
npm run docs:build           # refresh reference, then strict static build
npm run docs:check           # generated drift + built internal links and fragments
npm run docs:preview         # serve the production artifact on loopback :7794

docs:check requires an existing production build. It checks rendered local links and fragment IDs, site navigation, local assets and repository source-link paths at the linked Git revisions. Fetch origin/main before checking canonical-main links; the check uses local Git history without network access. External service availability is not part of this offline check. It also validates the documented action examples against the runtime schema and ensures generated references match current source.

Generated pages ​

scripts/docs-generate.mjs uses the TypeScript parser to extract exported type declarations with their attached documentation, plus the relevant schema/document declarations and model-facing tool envelopes. It uses the TypeScript 7 parser API already installed by the repository; that API is currently under an unstable export, so compiler upgrades need a reference-generation check. It reads the three JSON record schemas and creates required-field summaries and full schema blocks. It reads only named source files and schemas; it does not load the application.

The generated pages are committed so agents can read them directly. Do not edit them by hand. Source links navigate current main; they are not snapshot permalinks. SHA-256 hashes identify the exact bytes extracted from the checkout, independently of those navigation links. Generation does not depend on branch names or commit history, so source changes and refreshed references can be committed together and survive squash/rebase. Narrative source links retain their reviewed baseline permalinks. The selected source paths already exist on main; adding a new source path also requires ensuring its canonical-main link will be valid.

Updating explanations ​

When changing a contract:

  1. Refresh reference pages and inspect the diff.
  2. Update the narrative that explains the changed boundary, examples and implementation status.
  3. Update the narrative's reviewed revision/date and source links when revalidating it against a newer baseline.
  4. Run the production build and link check. Review desktop/mobile layout and search when browser preview is available.

Generated comments retain original wording. Historical milestone comments are source context, not promises that a feature has shipped. If a comment conflicts with runtime code, correct or qualify the explanation and flag the comment separately.

Framework and output ​

The default VitePress documentation theme supplies a persistent sidebar, local full-text search, page outline, keyboard navigation, light/dark mode and responsive mobile navigation. Small theme overrides add Caret's teal accent, readable type and visible focus outlines. The site does not require external fonts or analytics.

Files in docs/site/public/ are copied to the site root unchanged. logo.png is Caret's logo (the nav bar, favicon, README and the app icon in mac-helper/Resources/AppIcon.icns use it). labs/streaming-lab.html is a symlink to docs/interactive/streaming-lab.html, so the lab keeps its README, evidence and verifier next to it and the site publishes the same bytes; link to it with {target="_self"} so VitePress opens it as a page rather than a route.

docs/site/.vitepress/dist/ and cache files are ignored. To build for a subpath, use DOCS_BASE=/caret/ npm run docs:build and serve the output at that path. Use the same base when running checks. Publication is a separate action; no command here deploys or changes the installed Caret runtime.
